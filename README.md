# نظام إدارة التوصيل المصغر (Mini Delivery Management System)

نظام ويب متكامل ومتجاوب لإدارة عمليات وشحنات التوصيل بين **الزبائن (المتاجر)**، **مناديب التوصيل (السائقين)**، و**إدارة النظام (Admin)**، متصل بقاعدة بيانات **Firebase Realtime Database** ومبني باستخدام **HTML5, CSS3, Vanilla JavaScript (ES6+)** مع واجهة مستخدم عربية فاخرة بالهوية البصرية البنية والذهبية ودعم كامل لاتجاه RTL.

## 3. الأدوار وصلاحيات النظام (Roles & Permissions)

### 1. مدير النظام (Administrator)
- **إدارة الشحنات:** تتبع كافة الشحنات، تصفيتها حسب (المتجر، المندوب، المدينة، الحالة)، والاطلاع على سجل الحركات الكامل للشحنة (Audit Trail).
- **تنظيم الرحلات:** تجميع عدة شحنات في رحلة واحدة (`Trip`) وإسنادها إلى مندوب توصيل.
- **التسويات المالية:** عند عودة المندوب وتوريد المبالغ المحصلة، يؤكد المدير الاستلام وتتحول الشحنة من "تم التسليم" إلى "تسوية مالية جاهزة" لمنع التكرار المالي.
- **إدارة المتاجر والمناديب:** إضافة وتعديل وتفعيل أو تعطيل حسابات المتاجر والمناديب.
- **إدارة المدن والأسعار:** تعديل أسعار التوصيل المعتمدة وحفظها ديناميكياً في Firebase، وإضافة مدن جديدة.
- **معالجة طلبات السحب:** مراجعة طلبات سحب الأرصدة المقدمة من المتاجر والموافقة عليها أو رفضها.

### 2. الزبون / المتجر (Customer / Store)
- **إنشاء شحنة جديدة:** إدخال اسم المستلم، هاتفه، تفاصيل الشحنة، وقيمة البضاعة.
- **احتساب السعر التلقائي:** يتم اختيار المدينة واحتساب سعر التوصيل تلقائياً من خوادم Firebase دون إمكانية التلاعب اليدوي به.
- **متابعة الشحنات:** استعراض شحنات المتجر فقط في بطاقات فردية أنيقة ومتابعة مراحلها اللحظية.
- **المحفظة المالية:** الاطلاع على الرصيد المتوفر، وتقديم طلب سحب رصيد مالي إلى الإدارة.
- **حماية أمنية:** لا يمكن للمتجر تعديل حالات الشحنات يدوياً.

### 3. مندوب التوصيل (Driver / Representative)
- **عرض الرحلات المجمعة:** تظهر الرحلة كبطاقة كبرى (`Trip #001`) تضم بداخلها بطاقات الشحنات المحددة لها.
- **إجراءات التسليم:** أزرار سريعة للاتصال الهاتفي والمراسلة عبر WhatsApp للمستلم.
- **تأكيد التسليم:** يملك المندوب فقط صلاحية تحويل الشحنة من "قيد التوصيل" إلى "تم التسليم".
- **حماية أمنية:** لا يمكن للمندوب الاطلاع على شحنات مناديب آخرين، ولا يملك تعديل التسويات المالية أو إضافة شحنات لنفسه.

## 4. دورة حياة الشحنة الصارمة (Shipment Lifecycle)

تتبع كل شحنة تسلسلاً زمنياً صارماً ومحكماً في الكود وقواعد الأمان:

```text
[1] بانتظار الموافقة (Pending Approval)
         │
         │ يقوم المدير بتعيين الشحنة لمندوب أو ضمها لرحلة توصيل
         ▼
[2] قيد التوصيل (Out for Delivery)
         │
         │ يقوم المندوب بتسليم الطرد للمستلم وتحصيل المبلغ
         ▼
[3] تم التسليم (Delivered)
         │
         │ يقوم المدير بتأكيد استلام وتوريد المبلغ النقدي في الخزينة
         ▼
[4] تسوية مالية جاهزة (Ready for Settlement)
```

| الانتقال | المنفذ المصرح له | الملاحظات |
|---|---|---|
| بانتظار الموافقة ← قيد التوصيل | مدير النظام (Admin) فقط | عند إنشاء رحلة أو إسناد شحنة |
| قيد التوصيل ← تم التسليم | المندوب المعين للشحنة فقط | بعد التسليم الفعلي وتحصيل المبلغ |
| تم التسليم ← تسوية مالية جاهزة | مدير النظام (Admin) فقط | تضاف قيمة البضاعة لرصيد المتجر ويتاح السحب |

## 6. خطوات ربط وتهيئة مشروع Firebase

### الخطوة 1: إنشاء مشروع Firebase جديد
1. ادخل إلى [Firebase Console](https://console.firebase.google.com/).
2. اضغط على **Add Project** وأدخل اسم المشروع (مثل: `mini-delivery-system`).
3. اضغط متابعة حتى اكتمال إنشاء المشروع.

### الخطوة 2: تفعيل Realtime Database
1. من القائمة الجانبية في Firebase Console، اختر **Build** ثم **Realtime Database**.
2. اضغط **Create Database**، وحدد الموقع الجغرافي الأقرب إليك.
3. ابدأ في وضع الاختبار (**Start in test mode**) أو فعّل القواعد لاحقاً.

### الخطوة 3: تفعيل المصادقة (Firebase Authentication)
1. من القائمة الجانبية، اختر **Authentication** ثم اضغط **Get Started**.
2. في تبويب **Sign-in method**، اختر **Email/Password** واضغط تفعيل (**Enable**) ثم حفظ (**Save**).

### الخطوة 4: نسخ إعدادات الربط وتحديث ملف `JS/firebase-config.js`
1. من إعدادات المشروع (أيقونة الترس في الأعلى ← **Project settings**).
2. في تبويب **General**، انزل إلى قسم **Your apps** واضغط على أيقونة الويب (`</>`).
3. اكتب اسماً للتطبيق ثم انسخ كائن `firebaseConfig`.
4. افتح ملف `JS/firebase-config.js` واستبدل كائن `defaultFirebaseConfig` بقيم مشروعك:

```javascript
const defaultFirebaseConfig = {
    apiKey: "AIzaSy...",
    authDomain: "your-project.firebaseapp.com",
    databaseURL: "https://your-project-default-rtdb.firebaseio.com",
    projectId: "your-project",
    storageBucket: "your-project.appspot.com",
    messagingSenderId: "...",
    appId: "..."
};
```

> **ملاحظة ذكية:** يمكنك أيضاً حفظ إعدادات Firebase مباشرة من واجهة التطبيق عبر النقر على زر **"إعدادات الربط"** أو مؤشر Firebase في شريط الترويسة ولصق الإعدادات دون الحاجة لتعديل الكود البرمجي!

### الخطوة 5: تطبيق قواعد الأمان (Security Rules)
1. افتح تبويب **Rules** في صفحة **Realtime Database**.
2. انسخ محتويات الملف المرفق `database.rules.json` والصقها في المحرر ثم اضغط **Publish**.

### الخطوة 6: استيراد البيانات الأولية (Seeding)
- **الطريقة الأسهل:** بعد فتح التطبيق، اضغط على زر **"إعدادات الربط"** ثم اضغط زر **"تهيئة البيانات في Firebase الآن"**.
- أو من خلال Firebase Console: اضغط على الثلاث نقاط في Realtime Database ← **Import JSON** واختر ملف `database-schema.json`.

## 7. الحسابات التجريبية الأولية وطريقة إنشاء حساب المسؤول الأول

النظام مجهز مسبقاً بثلاثة حسابات تجريبية مفعلة:

| الدور | البريد الإلكتروني | كلمة المرور | الوصف |
|---|---|---|---|
| **مدير النظام** | `admin@delivery.ly` | `123456` | صلاحيات كاملة لإدارة النظام والرحلات والتسويات |
| **متجر النور** | `store@delivery.ly` | `123456` | زبون/متجر لإنشاء الشحنات ومتابعة رصيده وسحبه |
| **مندوب التوصيل**| `driver@delivery.ly` | `123456` | مندوب لتوصيل الشحنات واستلام المبالغ وتأكيد التسليم |

> **زر التعبئة السريعة:** توفر واجهة الدخول أزراراً سريعة أعلى النموذج (`المدير`, `متجر`, `مندوب`) تنقر عليها لملء البيانات فوراً!

### لإنشاء حساب مسؤول جديد في Firebase Authentication:
1. اذهب إلى Firebase Console ← **Authentication** ← **Users** ← **Add user**.
2. أدخل البريد وكلمة المرور واضغط إضافة، وانسخ الـ `UID` الخاص به.
3. اذهب إلى **Realtime Database** وأضف تحت المسار:
   `MiniDeliverySystem/users/admins/{UID}`
   ```json
   {
     "uid": "UID_المستخرج",
     "name": "اسم المدير",
     "email": "admin@example.ly",
     "phone": "0910000000",
     "role": "admin",
     "active": true,
     "createdAt": "2026-11-10T00:00:00.000Z"
   }
   ```

## 8. طريقة تشغيل المشروع محلياً (Running Locally)

المشروع مبني بتقنيات الويب القياسية بدون أي إضافات تجميع معقدة، ويمكن تشغيله بعدة طرق:

### الطريقة 1: عبر خادم Python المدمج
افتح موجه الأوامر (Terminal أو PowerShell) في مجلد المشروع ونفذ:
```bash
python -m http.server 8080
```
ثم افتح متصفحك على: `http://localhost:8080`

### الطريقة 2: عبر Node.js (npx serve)
```bash
npx serve .
```

### الطريقة 3: عبر إضافة Live Server في VS Code
انقر بزر الفأرة الأيمن على ملف `index.html` واختر **Open with Live Server**.

### الطريقة 4: الفتح المباشر
يمكن فتح `index.html` مباشرة بالنقر المزدوج في أي متصفح حديث (Chrome, Edge, Firefox, Safari). يدعم التطبيق وضع العمل المحلي والمحاكاة الذكية تلقائياً عند عدم الاتصال بالسيرفر.
